# 美工主动提案 v1.4.3
美工Work可自主选择页面、顺序、视觉布局交互及功能建议，并在 proposals/<自建唯一提案号>/vX.Y.Z/ 发布新提案；本README/TEMPLATE由coordinator维护，其他提案版本由对应美工维护，不互改。Work也可使用 previews/ 做不依赖正式任务派发的迭代草稿，并通过 GitHub Issue 发布反馈。
提案类型与数量不设单轮限制；功能建议注明目标、所需数据和待确认规则。是否安排商城实施由用户对具体提案版本、完整Commit及范围批准决定。不得为凑前后端职责制造接口；暂不知道已有能力就写unknown，由coordinator核查，别假定缺失。
必需PROPOSAL.md、实际可运行原型源码/必要素材与README、FEATURE_REQUESTS及独立PROTOTYPE_TEST结果（实际运行/未测分开）；可引用自己已有原型Commit但不覆盖历史。模拟后端明确标注，不把原型当商城开发完成。
提案版本修订新目录，记录supersedes；coordinator从Git核实最终完整Commit及提交时间，feedback记录审核结果。用户确认具体版本+完整Commit+授权范围并通知coordinator前，公开提案submitted只表示建议已提交，不是实施授权；前后端不得主动领取 GitHub 中的新提案。正式任务状态与feedback由coordinator维护，Work不可借提案或草稿更改。
提案交付仍遵守公开敏感信息与素材许可/编码规则，用户不手动中转。

草稿与正式交付分离：previews/ 可反复修改、提交和在线测试；它不替代本目录中的正式提案版本，也不得改写已提交历史。针对已批准设计实施中的缺陷使用GitHub Issue反馈，由coordinator判断是否属原范围返工。
