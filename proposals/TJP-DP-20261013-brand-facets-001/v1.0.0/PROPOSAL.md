## 場景與目的
訪客搜尋商品後，按「全部品牌 / 品牌名稱 + 件數」縮小結果，再清除篩選返回完整結果。只改搜尋結果頁的一個品牌快篩區塊，不改首頁、全站主題、購物車、價格或其他既有篩選。上線時保留原商品卡、排序、分頁、數量及加購功能，原型中不複製交易操作。

Work 已實際提交搜尋「耳机」：網站返回 3 件商品、商品卡、排序、每頁件數及列表切換。篩選與系列/口味/包裝/焦油量/價格按鈕在實測 DOM 中均為 disabled。未看到品牌快篩或品牌聚合件數，但這不是「後端不存在」的證明。既有 manufacturer_id 列表線索應優先復用。搜尋空結果 zzzxq_no_match_001 顯示共0件、暫無商品。詳細證據見 LIVE_BASELINE.md。

## 視覺與交互
沿用海軍藍、白、淡藍灰；僅新增白底圓角品牌面板，选中按钮深藍填色。無金框、促銷口號、付費誘導。PC：面板全寬，品牌按钮一行展示；過多時橫向滾動。手機：同一套資料與元件，44px 級觸控目標，品牌單行橫向滑動，原商品網格保持原站佈局。prototype 的示範卡PC四列/手機兩列，並非要求重做正式商品卡。

操作：選品牌→page重置1→loading→一致的商品/總數；清除→恢復全部；排序保留已選品牌；刷新分享URL恢复状态。空結果可重新搜尋，失敗保留條件並重試。快切時僅最新請求可更新UI。原型用 hash 保存條件，不替換正式站 route。

視覺稿：design-pc.svg（1363px）與 design-mobile.svg（393px），是人工編排示意，不是瀏覽器截圖。源碼 index.html 是實際響應式原型；PROTOTYPE_TEST.md明確未測視覺範圍。

## 真實前後端必要性
前端不可只在當頁商品中計數：首頁4件不能代表全部6件，也不可推斷隱藏/不可見商品。需要服務端對相同搜尋條件下的所有可公開匹配商品做 distinct product 計數與品牌聚合，並提供同一條件的品牌篩選結果。若既有介面已滿足，後端只需確認/調整及提供聯調證據，不另造API；若純前端已有足夠可靠資料，coordinator應返修此雙模組測試提案。

後端：確認現有列表/搜尋/manufacturer_id契約，擴充或復用公開資料的聚合回應，固定搜尋、品牌、排序、分頁語義；匿名只讀，不修改DB/訂單/庫存/會員。前端：增量面板、URL狀態、loading/error/empty、競態控制與可訪問性，通過真實接口聯調。接口契約候選見FEATURE_REQUESTS.md。

## 可檢驗驗收
1. 可控公開測試資料：同搜尋6件、A=2/B=3/C=1，頁長4。第一頁品牌數量仍為2/3/1；B選中總數3，卡片全屬B，品牌聚合保持2/3/1。
2. 按品牌和清除均reset page=1；排序不丟失品牌；URL刷新恢复篩選；查無商品/非法品牌按契約展示，不能洩漏隱藏商品。
3. 慢速網絡下連續A→B，A遲到回應不覆盖B；錯誤後可重試，原搜尋仍可用。
4. PC1363×936與手機393×852：文字清楚、觸控目標≥44px、只有品牌列可橫滾，頁面無水平溢出。鍵盤可操作、焦點可見、結果總數有live region。
5. 不變更付款/金額/訂單/庫存/權限，不隱藏現有卡片操作；開關關閉能恢復基線。
6. 前後端結果由coordinator核實，使用實際部署Commit+批准提案Commit+公開安全URL；收到用戶「進入美工復核」後Work雙端真實網站測試，獨立報pass/rework/not_tested。
